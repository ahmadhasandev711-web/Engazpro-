# الاختبارات المعمارية وضمان الامتثال (Architecture Guards)

مجموعة اختبارات آلية لحماية قواعد المعمارية الصارمة (`ARCHITECTURE_RULES.md`) ومنع تسرب أي مخالفات جديدة لكود المشروع.

---

## مبدأ السقاطة (The Ratchet Principle)

جميع ملفات الـ Baseline في هذا المجلد تعمل باتجاه واحد فقط نحو الأسفل (**الـ Baseline ينزل بس**):
1. **حظر أي مخالفة جديدة:** ظهور أي مخالفة في ملف جديد أو دالة جديدة يفشل الاختبار فوراً.
2. **حظر تفاقم المخالفات:** زيادة طول دالة مسجلة أو زيادة عدد الاستعلامات يفشل الاختبار فوراً.
3. **إلزامية خفض السقف عند الإصلاح:** إذا قمت بإصلاح مخالفة (مثلاً اختصرت دالة لتصبح $\le$ 30 سطراً، أو نظفت Controller من الاستعلامات)، **سيفشل الاختبار عمداً** حتى تقوم بإزالة المخالفة أو تقليل رقمها في ملف الـ Baseline المقابل.

## كيف تتصرف عند إصلاح مخالفة؟

1. بعد إعادة هيكلة الكود واختصاره، شغّل الاختبارات المعمارية:
   ```bash
   php artisan test --testsuite=Architecture
   ```
2. ستظهر لك رسالة تفيد بأن هناك تحسيناً تم رصده (مثلاً: `[مخالفة تم إصلاحها!]`).
3. افتح ملف الـ JSON المذكور في رسالة الفشل داخل `tests/Architecture/baselines/`:
   - إذا تم اختصار الدالة إلى 30 سطراً أو أقل: **احذف سطر الدالة بالكامل** من `method-length.json`.
   - إذا تم تقليل الاستعلامات أو كتل الـ try: **عدّل الرقم للعدد الجديد الأقل**.
4. أعد تشغيل الفحص لترى الضوء الأخضر 🟢، واعمل commit للملف المعدل مع الكود.
